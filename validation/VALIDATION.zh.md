# 模型验证 —— V100 & H200

对 [MODEL_AND_RESULTS.zh.md](../MODEL_AND_RESULTS.zh.md) 的功率—吞吐解析模型做三项验证：**吞吐曲线的精度**、
**效率最优功率的精度**、**与更简单解析形式的对比**。两块硬件、8 workload × 2 相（Qwen3-4B 仅有 V100
数据、无法跨硬件对照，全程排除）。

被验证的模型（实现见 [`fitlib.py`](../pt_cap_gpu1/portfolio/fitlib.py) 的 `fit_*_theory`，与论文图和机架
求解器共用同一份拟合，不另起炉灶）：

$$X_{\mathrm{pre}}(P)=a\,\phi(P),\qquad
X_{\mathrm{dec}}(P)=\Big[\max(a/x,\,b)+\max(c/x,\,d)+e\Big]^{-1},\qquad
x=\phi(P)=\Big(\tfrac{P-P_{\mathrm{stat}}}{\chi}\Big)^{1/\gamma}$$

> 复现：`python3 validation/validate_model.py` → 4 张图 + 4 个 CSV。

## 0. 实验设置、定义域与标定

| | V100 | H200 |
|---|---|---|
| 数据 | [`pt_cap_gpu1/portfolio/data/`](../pt_cap_gpu1/portfolio/data/) | [`data_h200/`](../data_h200/) |
| decode | cap 扫描 100–250 W | cap 扫描 200–700 W |
| prefill | cap 扫描 100–250 W | **锁频扫描**（cap 固定 700 W），功率轴取实测功耗 |
| $f_{\max}$ / 时钟下限 | 1530 / 135 MHz | 1980 / 345 MHz |

**定义域 = cap 真正可控的 DVFS 区**（`fitlib.cap_sweep_mask`，拟合、图、指标、机架求解器四处共用同一
判据）。cap 扫描中两类点被剔除：

- **时钟地板点**：cap 低到 DVFS 够不着，驱动靠失速凑功率——同一时钟出现两个吞吐（相差 2–2.5 倍），
  任何 $X=f(\phi)$ 都无法描述。H200 decode 每 workload 剔 1–3 个（底部 cap）。
- **调速器失速点**：实测功耗远低于 cap（< 0.88×）且时钟远离量程顶（< 0.9×）——cap 与 boost 都不是
  约束，调速器在自钳振荡，均值时钟高估了吞吐加权的有效时钟（V100 chat prefill @cap 100 W：实吃
  **73 W**、时钟 441/1302，T/φ 崩到中段的 62%）。V100 剔 6 个（5 个轻载 prefill 的 100 W 点 +
  classify decode 的 100 W 点）。
- **保留**健康的轻载欠吃点（时钟顶着量程顶、workload 本身轻，如 H200 summarize decode 高 cap
  段）——那是饱和平台的证据，不是病态。锁频扫描（H200 prefill）不适用本判据，逐点保留。

**功率侧标定（式 3–4）**：$(P_{\mathrm{stat}},\gamma)$ **按 GPU × 相**在全部序列上池化标定、在使用方向
（由 P 反解 φ 对实测时钟）拟合；每 workload 只留 $\chi$（活动因子 α 对应项，闭式最小二乘）：

| | prefill | decode |
|---|---|---|
| **V100** | $P_{\mathrm{stat}}$=86.2 W · $\gamma$=**2.56** | 91.2 W · $\gamma$=**4.13** |
| **H200** | 215.1 W · $\gamma$=**1.46** | 210.8 W · $\gamma$=**1.52** |

**拟合损失口径**：部署拟合（`fit_*_theory`）在 **φ(P) 上以相对残差**拟合——曲线在对数轴上展示、
按 MAPE 打分，绝对损失会让最慢的点独占拟合（H200 summarize decode 仅 6–33 tok/s，其底部点曾拽偏
整条曲线：H200 decode 中位 MAPE 4.2%、最差 7.9%；改相对损失后 **1.7% / 4.2%**）。数据**不做任何
预处理**，原始 CSV 原样进入拟合。

**一次由验证反向抓出的数据错误**：translate-qwen3b H200 decode 曾长期 MAPE ~10%，逐点诊断集中在
cap 313 W 一点（实测 602、预测 807，+34%）。查该文件的提交史：**原始实测是 800.9→802.0**（时钟
441 MHz 未变），后续某次提交把它改成了 602——同时钟不同吞吐违反物理，且 602 使 T/clk 比值跳出全列
趋势。恢复实测值后该点残差 0.7%、整条曲线 MAPE 1.97%。模型自始至终是对的。

三点偏离论文表述、需在文中修正或注明：

1. **$\chi$ 不能钉死为 $P_{\max}-P_{\mathrm{stat}}$**（式 3 的写法）：那等于断言 $f_{\max}$ 时吃满
   TDP，与论文自己的立论（"actual draw rarely reaches the TDP"）矛盾；实测下强制该式使 MAPE 恶化一个
   量级（V100 中位 3.3→14.6%、H200 5.0→52.7%）。
2. **有效 $\gamma$ 需按相标定**：论文已区分 $\eta_C^{\mathrm{pre}}/\eta_C^{\mathrm{dec}}$，有效功率指数
   同理——V100 两相 $\gamma$ 相差 1.6（合并标定 2.88 会把 prefill 的解析效率峰压低 ~30 W）；H200 两相
   几乎一致，分相无副作用。
3. **$\gamma\in[2,3]$ 的区间断言不成立**：4 个标定值里 3 个在区间外（H200 两相 ~1.5：扫描深入定压区，
   $P\propto f$ 拉低有效指数；V100 decode 4.13：utilization 随频漂移被吸收进指数）。论文该句应限定为
   "电压可调区内的裸 V/f 指数"，或直接按实测报有效值。

## 2. 效率曲线的精度（Check 2）

效率 = tok/s ÷ **实测功耗**（与 [`curves_lib.py`](../workload_analysis/curves_lib.py) 同口径）。模型效率
曲线 = 拟合吞吐 ÷ 实测功耗插值，与实测效率点按 **MAPE** 对比——和 Check 1 同一准则，落在规划器
真正优化的 tok/J 轴上。

| 硬件 | 效率曲线中位 MAPE |
|---|--:|
| **V100** | **2.6%** |
| **H200** | **2.0%** |

图 [`fig_val_peff.png`](fig_val_peff.png)（`fig_workload_power_tokj.png` 同款面板：3 行硬件（含
5090-MOCK）× 7 类，逐相标 MAPE；圆圈标出效率甜点，仅作展示、不参与打分），数据
[`val_peff.csv`](val_peff.csv)。

- **在实测栅格点上功耗分母左右相消，效率 MAPE 与吞吐 MAPE 数值恒等**——本节提供的是同一精度在
  效率轴上的视图（峰的位置与平坦度直接可见），不是新指标。
- **早前按"最优点偏差 ΔP"报告的版本已弃用**：效率峰二阶平坦，argmax 位置病态——顶部 <2% 的曲线
  误差即可把最优点移动 ~80 W（如 Assistant API H200 decode：489–626 W 的 137 W 窗口内实测效率仅变
  2.6%），而放错 cap 的效率代价接近零。峰位不是该验证的量；这个平坦性本身正是"cap 放在效率峰附近"
  规划策略稳健的原因。

## 3. 与更简单解析形式的对比（Check 3）

两个基线拟合到**同一批数据**、共用**同一套功率侧**，仅吞吐侧结构不同；三者统一用相对残差最小二乘拟合
（与 MAPE 打分口径及 §0 的部署拟合口径一致；本节独立重拟合、只比结构，故 ours 数值与 §1 略异）：

| 形式 | 表达式 | 自由参数 |
|---|---|--:|
| **A** | $X=a\,x^{p}$ —— 经典 DVFS 单一幂律，无分段 | 2 |
| **B** | $X=\min(a\,x^{p},\,X_{\max})$ —— 幂律 + 硬带宽上限，无混合段 | 3 |
| **ours** | 两 roofline 之和，三段 | 5 |

**decode（中位 MAPE %）**，饱和段 = 定义域功率区间上半程（数据侧定义，避免用 ours 自己的分界功率
划界的循环论证）；完整数据 [`val_baselines.csv`](val_baselines.csv)，图
[`fig_val_baselines.png`](fig_val_baselines.png)：

| 硬件 | 全程 A / B / ours | **饱和段** A / B / ours | 留一 CV A / B / ours |
|---|--:|--:|--:|
| **V100** | 2.44 / 2.44 / **2.37** | 1.37 / 1.37 / **0.51** | **10.2** / 10.2 / 12.1 |
| **H200** | 4.79 / **4.45** / 5.28 | 1.15 / 1.15 / **0.91** | 14.3 / **14.2** / 15.1 |

**prefill（中位 MAPE %）**：

| 硬件 | 全程 A / B / ours | 饱和段 A / B / ours | 留一 CV A / B / ours |
|---|--:|--:|--:|
| **V100** | **2.54** / 2.54 / 3.65 | **1.75** / 1.75 / 2.66 | 8.9 / **8.3** / 10.1 |
| **H200** | 5.37 / 5.49 / **5.18** | 2.69 / 2.69 / **1.77** | 16.6 / 16.6 / **15.2** |

**读数（其中一条对本模型不利）**：

1. **decode 全程打平、饱和段是主场**：V100 饱和段误差降到 **1/2.7**（0.51 vs 1.37），H200 0.91 vs 1.15。A 在高功率端必然过冲（幂律无上界），B 的硬截断有折角，实测是平滑过渡——混合段的存在
   可观测。
2. **留一 CV decode 侧 ours 略输**（12.1 vs 10.2、15.1 vs 14.2）：5 个自由参数在 7–8 个扫描点上没有
   赚回来。表述应为：三段结构在饱和段真实可测，但以当前扫描密度，自由拟合它不比简单形式更能外推。
3. **prefill 的方向相反且支持理论**：ours 的 $X\propto\phi$ 是 A 在 $p{=}1$ 的受约束特例，样本内
   通常不优（V100 付 1.1 个百分点）；而 H200 上 ours **全程、饱和段（1.77 vs 2.69）、留一 CV
   （15.2 vs 16.6）三项全部反超**自由指数的 A/B。"prefill 全程计算受限、吞吐线性于 φ"（§III-A3）
   在数据上站得住。

## 4. 局限

- **两个 roofline 项不可分辨（最重要）**：decode 拟合中 $a{=}c$、$b{=}d$ 精确成立的比例为**两块硬件
  各 5/8**——单条 P–X 曲线只能定出两项之和，定不出各自；此时 $P_{\mathrm{attn}}$ 与 $P_{\mathrm{lin}}$
  重合，拟出的模型退化为两段。§3 的饱和段优势只支持"平滑饱和"形状，**不构成对"注意力先于线性部分
  切换"机理的直接验证**。正解是由结构参数（式 5–7、11）直接算出 $a,b,c,d$ 与分界功率、只标定
  $\eta_C,\eta_M,k_{\mathrm{act}},T_0$；`results/model_info.json` 已有所需字段但未覆盖 portfolio 全集。
- **扫描点稀疏**：滤域后每条 6–11 点，留一 CV 绝对值（8–16%）远高于样本内 MAPE——外推能力受限于
  数据量而非模型形式。
- **H200 decode 未进平台**：700 W 内多数 workload 仍在上升段，Check 2 的 2 个边界受限点与饱和段
  样本仅 3–4 点由此而来。
- **prefill 两硬件口径不同**：V100 cap 扫描、H200 锁频扫描（横轴实测功耗，无 cap 强制误差），跨硬件
  比较需注意。
- **合成锚与 MOCK 数据不参与验证结论**：Long-context chat 的合成锚只在按类图中展示（其"MAPE"是对
  合成点的拟合优度）；RTX 5090 行仅为展望。
- **未验证 goodput**（式 15–17）：SLO 约束下的 $P_{\min}$ 反解无实验对照。
