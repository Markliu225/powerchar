# ⚠ MOCK RTX 5090 数据集 —— 合成数据，未做任何实测

本目录**没有一个数字来自真实 RTX 5090**。用途：在 5090 硬件到手之前，让论文管线
（曲线图、机架求解器）能以 Table II 的 5090 场景跑通并预估结果形态。

## 生成方式（`make_mock_5090.py`，seed 5090，可复现）

1. **形状源**：每个 workload 取 **H200 实测数据**，用仓库自己的解析模型拟合
   （`fitlib.fit_*_theory`，标定功率侧）。
2. **规格缩放**（有效达成值之比，非 datasheet 峰值之比）：
   计算 ×0.72 · 带宽 ×0.95 · 每步开销 ×0.85（理由见脚本 docstring）。
   prefill 斜率锚定 H200 **实测最高点**（防止线性外推反超 H200）。
3. **功率侧**：式 (3)，消费卡常数 P_stat=150 W、γ=2.7、F_MAX=3090 MHz、
   持续 boost 上限 ~2890 MHz；χ 按 H200 各序列的满载功耗占比缩放（±6% 每序列抖动）。
   prefill 的无约束满载目标设为 ~1.35×TDP——重载张量负载在 575 W cap 下会真实降频
   （顶端时钟 ~2565 MHz，降约 17%），而不是贴着 cap 只降一两档。
4. **模拟扫描** + 小噪声（吞吐 0.8%、功耗 0.6%），时钟量化到 15 MHz 步进：
   - decode：**cap 扫描 [200, 575] W**（几何栅格，密度与 H200 扫描一致）；
   - prefill：**锁频扫描**（810→3090 MHz，cap 固定 575 W），顶端复现 power_limited 降频；
     810 以下动态功耗淹没在噪声里、P→φ 反解病态，只会产生一个偏离曲线的杂点，故不采。

格式与 `data_h200/`（v4 方法学）逐列一致，下游工具无需改动。

## 已知的构造性局限

- 一切数值继承 H200 的实测偏差；×0.72/×0.95 是**假设**，不是测量。
- 排序约束（V100 < 5090 ≤ H200）是构造出来的，不是发现。
- 由数据反标定的功率侧（P_stat≈141、γ≈2.31）与生成参数（150、2.7）略有偏差，
  来自 boost 天花板截断——真实卡也会有类似效应，但幅度未知。
- **prefill 严格线性于时钟**（生成模型即 X=a·φ），与拟合形式相同——因此**不能**拿本数据集
  做模型验证，那是循环论证；validation/ 有意不含 5090。
- 机架 CSV 里 `opt_w_measured` 可超预算 ≤0.4%（cap 执行松弛 ±1% 噪声所致），引用功率数字时注意。
